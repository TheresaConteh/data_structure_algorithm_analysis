# Stack-Based Expression Evaluator (Object-Oriented, Unit-Tested)

**Course:** DCOMP320 Data Structures and Algorithms
**Assignment:** Individual Assignment (10%), Stacks Implementation
**Author:** Abdulai Bah, Limkokwing University of Creative Technology, Sierra Leone

Reads maths expressions from `input.txt`, evaluates each one using two stacks, and writes the answers to `output.txt`. The code is organised into classes (`Stack`, `Tokenizer`, `ExpressionEvaluator`, `FileProcessor`), uses Python's `Decimal` for exact arithmetic (`0.1 + 0.2` is exactly `0.3`), and ships with 17 automated unit tests.

## How to run
Requires Python 3.6 or later. No extra libraries needed. Run it from any folder: the program finds `input.txt` next to itself. On Windows, use `py` if `python` is not recognised.

```
python stack_evaluator.py              # reads input.txt, writes output.txt
python -m unittest test_evaluator -v   # run the 17 automated tests
python stack_evaluator.py in.txt out.txt   # use other file names
```

## Input and output file formats
**input.txt**: one expression per line. Expressions are separated by a line of dashes (`-----`).
**output.txt**: the same layout. Each expression line is replaced by its result and every separator line is copied unchanged.

```
input.txt                  output.txt
3 + 5 * 2                  13
-----                      -----
(8 / 4) + 7 * 2            16
-----                      -----
10 - (2 + 3) * 4           -10
```

## How it works
- **Stack:** the LIFO data structure (`push`, `pop`, `peek`, `is_empty`, `size`).
- **Tokenizer:** turns text into `Decimal` numbers, operators and brackets, and recognises negative signs.
- **ExpressionEvaluator:** uses a value stack and an operator stack (shunting-yard method). Raises `EvaluationError` for bad input.
- **FileProcessor:** reads `input.txt`, copies separators, writes `output.txt`, and reports how many answers and error lines were written.

## Why `Decimal`?
Normal floating-point numbers give `0.1 + 0.2 = 0.30000000000000004`. With `Decimal` the answer is exactly `0.3`, which matters for money-style calculations.

## Testing
- `python -m unittest test_evaluator -v` runs 17 tests covering the stack, the three handout examples, precedence, brackets, negatives, exact decimals, every error type, whitespace, large numbers, rounding, and a full file round trip that checks separators are kept.
- All 27 cases in `input.txt` were also checked against an independent calculator that uses exact fractions and no stacks. All results matched.

## Assumptions and limitations
- Supported: `+ - * /`, brackets `( )`, decimal numbers (`2.5`, `.5`) and negative numbers (`-5 + 12`, `2 * -3`, `-(2 + 3)`).
- Standard precedence: `*` and `/` before `+` and `-`; equal precedence is worked left to right (`100 / 4 / 5 = 5`).
- Whole-number results print without a decimal point (`13`). Other results print up to 4 decimal places (`10 / 3` gives `3.3333`).
- Division is true division: `7 / 2 = 3.5`.
- A bad line never stops the program. Its output line shows a message instead (`Error: division by zero`, `Error: mismatched parentheses`, `Error: malformed expression`, `Error: invalid character 'x'`) and all other lines are still processed.
- Blank lines are copied as blank lines. A separator is any line made of three or more dashes.
- Not supported: exponents (`2 ** 3`), variables, functions, implicit multiplication (`2(3 + 4)`), scientific notation (`1e3`).

## Note on the handout example
The handout lists the answer to `(8 / 4) + 7 * 2` as 17. The correct answer is 8 / 4 + 7 x 2 = 2 + 14 = **16**, so the program outputs 16. This is deliberate and is explained in the report.
